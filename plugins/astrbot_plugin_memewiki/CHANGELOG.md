# CHANGELOG

## 1.5.2 — 2026-10-26

**修：Windows 上更新插件报 `WinError 32 另一个程序正在使用此文件`。**

- `memes.db` 以前在插件加载那一刻就打开、连接一直缓存在进程里；而 AstrBot 更新插件是「先删旧插件目录 → 再解压覆盖 → 最后才 reload」，reload 里才会调 `terminate()`。Windows 上文件被占用就删不掉也写不进，更新直接失败（Linux 不受影响，所以一直没发现）
- 现在改成**每次查询开一个只读连接、用完立刻 close**：插件任何时刻都不持有 `memes.db` 句柄，更新/重装/删除插件都不会再撞锁。（启动时那行「词库 6668 条」日志改成读一次就关连接）
- 行为不变：查询仍是毫秒级；每日同步跑完照旧自动换库，不用重启
- 修（审查遗留）：`_load_slang` 读的是插件包里的 `group_slang.json`，而这文件从来没随包发布过（1.5.0 审查也提过这条）；现在改读**插件数据目录**里的同名文件，属于可选私货——不放就是空字典，不再有「包里缺文件」的嫌疑

## 1.5.1 — 2026-10-26

**配置少填字，词库跟着更新。**

- `/梗` 的回复形式改成**下拉选项**（图片卡片 / 纯文字）：以前得在配置里手填 `image` / `text`，拼错还会静默退回纯文字
- **联网方式三个开关合成一个下拉**：`miss_hint_enabled`（提示模型去搜）+ `search_fallback_enabled`（插件代搜）+ `search_mode`（联网方式）功能重叠、能配出「代搜但不提示」这种没人要的组合，现在只留 `search_mode`：`auto`（插件先搜，搜不到再提示模型，推荐）/ `plugin`（只代搜）/ `model`（只提示模型）/ `off`（完全关闭）；旧配置自动按两个布尔换算成对应模式，聊天里 `/网搜` 也支持这四个值
- 自动同步从「每周」改成「**每天**」：同步时刻仍可配（`auto_sync_hour`，默认 04:00），去掉 `auto_sync_weekday`
- `search_max_chars` 默认 **8 → 10**：像「已取餐」「什么水平」这类 9–10 字的短词现在也会联网查（整句闲聊照样挡掉）
- 修：同步跑完后进程里还连着旧库，新词库得重启才生效；现在同步结束自动关连接重开
- 修：`scripts/sync_memes.py` 一直没写 `items.json`，自动同步最后「重建 SQLite」那一步会静默失败——索引更新了、词库其实没动
- 修：slug 是整句的词条，URL 编码后文件名超过 255 字节，同步会抛 `OSError: File name too long` 直接中断；现在跳过并计数，另加 `--reuse-items`（复用已抓列表，重跑不用重拉 6600 条）
- 词库刷新：按 cnmeme.wiki 公开 API 重抓一次快照，**6660 → 6668 条**

## 1.5.0 — 2026-10-26

**预查只查本地，只在该搜的时候联网，同一个词不重复搜。**

词库没收录就联网，听起来合理，实测很浪费：群里 78% 的「梗查询」其实是「我是谁」「情绪」「你今天怎么样」这类闲聊整句，每次白花 0.4–1.4 秒和 900 字上下文。

- **先查本地**：群内梗 → 自定义黑话 → 内置词典，实测 **0.1–0.9ms**，命中就注入，不联网
- **闸门**：本地没有时，只有「明确在问梗」（什么梗 / 啥意思 / 出处 / 谐音 / 缩写…）或「像词条的短词」（≤ `search_max_chars` 字、不含疑问成分、不是你 / 我开头的整句）才联网
- **结果缓存**：同一个词 10 分钟内只搜一次；重复词折叠后共用缓存（`杂鱼杂鱼` → `杂鱼`、`666666` → `666`）
- 修：负缓存命中时不再重复联网（原来只有 `off` / `model` 模式才真跳过）
- 修：词库里有 27 个单字条目（乐 / 典 / 给 / 笑 / 绷…），「给我跪下」会误命中「给」—— SQL 分支补上 `length(title) >= 2`

**配置项对齐**：插件的自建搜索源早就删了，配置里却还留着。

- 删掉 `search_provider` / `search_api_key`（插件不再自带搜索源，只借用 AstrBot 的网页搜索；留着只会让人以为还得自己填 key）
- 新增 `search_mode`（`auto` / `plugin` / `model` / `off`），以前这个只有聊天里的 `/网搜` 能设
- 新增 `search_max_chars`（默认 8）：`_worth_search` 之前把 8 字写死在代码里，配置不生效
- README 重写「词库没收录时」整节，明确 **插件不存任何 API Key，也没有自己的搜索源**

实测同一串 8 条消息（杂鱼 / 杂鱼杂鱼 / 杂鱼杂鱼杂鱼 / 666 / 666666 / 不是你自己发的 / 这杂鱼是你说的 / 已取餐）：**联网 8 次 → 3 次**，其余 5 条复用缓存（0ms）或被闸门挡掉。

## 1.4.9 — 2026-10-26

**词库没收录时自动联网兜底，不再装懂。**

- 必须先查词库；没收录时按顺序兜底：
  1. 复用 AstrBot 已配置的搜索（deepseek/baidu/tavily/serpapi/brave/exa/bocha/firecrawl/anysearch）
  2. AstrBot 没配或失败 → 用插件自己的搜索源（tavily/serpapi/baidu + key）
  3. 都失败 → 让模型说不知道或反问「这什么梗」
- 新增配置：`search_fallback_enabled` / `search_provider` / `search_api_key` / `search_timeout` / `miss_hint_enabled`
- 负缓存命中时也会走兜底（原来 10 分钟内同词查询是静默失败）

## 1.4.5 — 2026-10-25

**修复：新加的黑话要等 10 分钟才生效。**

- 根因：预查有 10 分钟「未命中缓存」。某个词查过一次没结果后会被缓存，
  期间用户再 `/黑话` 加它，预查仍然直接跳过 → Bot 像没听见一样。
- 现在 `/黑话` 新增/更新/删除、以及面板编辑，都会清掉该词的未命中缓存，
  **加完立刻生效**。
- 实测：`wxhn` 之前三次都没识别，修复后 `lookup("wxhn")` 直接返回「我喜欢你」。
